# Mock Bank (가상 금융 서버)

핀타겟 시연용 가상 금융 서버입니다. 실제 은행처럼 거래(결제)를 발생시켜 핀타겟 메인 서버로 전달하는 용도이며,
메인 서버와 별개의 Spring Boot 프로젝트입니다.

거래가 생기면 먼저 mock-bank에 저장한 뒤, 핀타겟 메인 서버의 웹훅(`POST /api/webhooks/bank-transactions`)으로 보냅니다.

## 실행

```bash
cd mock-bank
MOCK_BANK_USERNAME=<계정> MOCK_BANK_PASSWORD=<비밀번호> \
FINTARGET_BASE_URL=<메인 서버 주소> FINTARGET_WEBHOOK_KEY=<웹훅 키> \
./gradlew bootRun
```

| 환경변수 | 필수 | 설명 |
|---|---|---|
| `MOCK_BANK_USERNAME`, `MOCK_BANK_PASSWORD` | O | 화면 로그인(Basic Auth) 계정 |
| `FINTARGET_BASE_URL` | X | 메인 서버 주소. 기본값 `http://localhost:8080`. 운영 서버로 보낼 때는 운영 주소 |
| `FINTARGET_WEBHOOK_KEY` | O | 메인 서버 `.env`의 `BANK_WEBHOOK_KEY`와 같은 값 |

- 웹훅 키는 비밀값입니다. 운영 서버에서 직접 확인하고, GitHub·메신저·문서에 붙여넣지 마세요.
  ```bash
  ssh -i ~/.ssh/fintarget.pem ubuntu@<서버 IP> 'grep ^BANK_WEBHOOK_KEY= ~/FinTarget-BE/.env'
  ```

- 주소: http://localhost:8081 (메인 서버 8080과 겹치지 않게 8081 사용)
- 브라우저 접속 시 Basic Auth 로그인 창이 뜨면 위 계정으로 로그인합니다.
- 필수 환경변수가 없으면 앱이 시작되지 않습니다.
- 데이터는 H2 파일 DB(`mock-bank/data/`)에 저장되어 재시작해도 유지됩니다. 초기화하려면 앱을 끄고 `data/` 폴더를 지우면 됩니다.

## 화면

- **결제 발생**: 핀타겟 사용자 UUID, 금액, 카테고리, 설명(가맹점), 결제 날짜를 입력해 거래 1건을 만듭니다.
  - 금액은 0보다 커야 하고, 결제 날짜는 오늘(한국 시간)보다 미래일 수 없습니다.
  - 직접 입력한 거래는 실제 은행처럼 같은 내용이어도 그대로 저장합니다.
- **최근 거래**: 최근 20건과 웹훅 상태를 보여줍니다.

  | 상태 | 의미 |
  |---|---|
  | `PENDING` | 아직 보내지 않음 |
  | `SENT` | 핀타겟이 새 지출로 저장함 |
  | `DUPLICATE` | 핀타겟에 같은 지출(사용자·날짜·카테고리·금액·설명)이 이미 있어 건너뜀 |
  | `FAILED` | 전송 실패 (서버 꺼짐, 키 불일치, 존재하지 않는 사용자 등). 실패 사유는 화면 위쪽에 표시 |

- **미전송·실패 거래 재전송**: `PENDING`·`FAILED` 거래를 다시 보냅니다. 핀타겟이 중복을 판정하므로 여러 번 눌러도 지출이 중복 저장되지 않습니다.
- **시연용 데이터** (입력한 사용자 UUID로 생성하고 바로 핀타겟으로 보냄)
  1. **기준선 생성**: 이번 달을 뺀 직전 3개월 동안, 매달 모든 카테고리에 2~3건씩 만듭니다.
  2. **랜덤 거래 10건**: 이번 달 1일 ~ 오늘 사이 날짜로 카테고리·금액이 랜덤인 거래를 만듭니다.
  3. **식비 급증**: 이번 달 식비 합계가 이전 달들의 식비 월평균의 2배 이상이 되도록, 부족한 만큼 이번 달 1일 ~ 오늘 사이 날짜로 만듭니다.
     기준선이 없으면 만들지 않고 안내 메시지를 보여주며, 이미 2배 이상이면 새로 만들지 않습니다.
  - 시연 데이터는 같은 사용자의 (날짜, 카테고리, 금액, 설명) 조합이 기존 거래와 겹치지 않게 만듭니다. 메인 서버가 이 조합으로 중복을 판정하기 때문입니다.

카테고리는 메인 서버가 쓰는 값과 같습니다: 식비, 교통, 카페, 쇼핑, 문화생활, 통신, 의료, 구독

## 시연 순서 (이상 지출 넛지)

1. **지출 데이터가 없는 시연 전용 계정을 사용할 것** (메인 서버는 이번 달 이전 전체 기간으로 평균을 내므로, 다른 지출이 섞이면 넛지가 뜨지 않을 수 있음)
2. 핀타겟 앱에서 그 계정의 사용자 UUID를 확인해 화면에 입력합니다.
3. `FINTARGET_BASE_URL`을 그 계정이 있는 메인 서버로, `FINTARGET_WEBHOOK_KEY`를 그 서버의 키로 설정해 실행합니다.
4. ① 기준선 생성 → ② 랜덤 거래 10건 → ③ 식비 급증 순서로 누르고, 결과 메시지에 실패 없이 "저장 n건"이 나오는지 확인합니다.
   실패가 있으면 위쪽 빨간 메시지의 사유를 해결한 뒤 "미전송·실패 거래 재전송"을 누릅니다.
5. 핀타겟 앱의 넛지 목록(`GET /nudges`)을 열어 "이번달 '식비' 지출이 평소보다 …% 늘었어요" 넛지를 확인합니다.
   넛지는 지출이 저장될 때가 아니라 넛지 목록을 조회할 때 만들어집니다.

## 테스트

```bash
cd mock-bank
./gradlew test
```

테스트는 메모리 H2와 테스트 전용 설정(`src/test/resources/application.yml`)을 사용하고, 메인 서버 호출은 흉내 내므로 환경변수나 메인 서버가 필요 없습니다.
