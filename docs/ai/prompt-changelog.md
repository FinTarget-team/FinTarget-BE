## 정책 조건 추출 프롬프트

정책 원문에서 소득 기준·본인 소득 상한·무주택 필수 여부·신청 대상(개인/사업자)·신청 가능 지역을 추출해 정책 추천 필터·정렬에 쓴다 (#220). 버전이 바뀌면 저장된 조건과 버전이 달라 전체 정책을 다시 추출한다.

| 버전 | 적용 | 변경 내용 | 변경 이유 | 평가 결과 |
|---|---|---|---|---|
| `policy-condition-v3` | #227 (현재 운영) | 출력에 특정 대상 전용 여부 specialTarget(boolean, 판단 불가 null)과 대상 집단 specialTargetGroup(true일 때만) 추가. 기준: 온보딩 정보(나이·소득·지역·주택·직업 유형)로 해당 여부를 알 수 있으면 false, 알 수 없는 집단 한정이면 true. true 예시: 신혼·예비부부, 임산부·출산가구, 농어업인, 예술인, 특정 학교·기관 소속, 자립준비청년, 장병, 가족돌봄청년, 장애인, 수급가구, 한부모, 다문화, 북한이탈주민, 경계선지능. false 예시: 대학생 전체, 재직자·구직자, 중소기업 재직자, 창업자. 사업자 여부는 targetType으로 판단, 우대·가점 조건일 뿐이면 false. 예시 4개에 필드 추가, 자립준비청년 예시 1개 추가 | 추천 상위 N에 자립준비청년·장병·가족돌봄청년처럼 대부분의 사용자가 받을 수 없는 특정 대상 전용 정책이 들어옴 | 로컬 전체 재추출 (#227 PR 참고) |
| `policy-condition-v2` | #225 | 출력에 경제적 혜택 유형 benefitKind 추가 (MONEY: 현금·적립 매칭·이자·보증료·실비, COST_SAVING: 바우처·할인·감면·저렴한 임대·무료 물품, LOAN: 일반 대출, NON_FINANCIAL: 상담·교육·행사·공간 운영, NOT_FOR_INDIVIDUAL: 기관·단체 지원·시설 조성, UNKNOWN). 개인이 돈·비용 절감을 실제로 받으면 다른 지원이 섞여 있어도 MONEY·COST_SAVING, 참석 실비·소액 기념품은 NON_FINANCIAL, 사업 예산·단체 보조금은 개인 혜택 아님, 만남·연결의 "매칭"은 금전 혜택 아님. 시·군·구 한정 여부 localScope(boolean, 판단 불가 null) 추가. 예시 4개에 benefitKind·localScope 추가 | 추천 상위 N에 상담·교육·행사 같은 비금전 정책이 섞이고, #162 혜택 유형(SERVICE)으로는 바우처·할인과 교육·상담을 나눌 수 없음 | 로컬 864건 재추출 (#225 PR 참고) |

## 정책 추천 리랭킹 프롬프트

규칙 기반 추천 후보(최대 50건) 중 사용자에게 가장 맞는 최종 N건(기본 10)을 상위 모델(`openai.model.premium`)이 고른다 (#229). 버전은 사용자별 메모리 캐시의 입력 해시에 들어가므로 올리면 모든 사용자를 다시 계산한다.

| 버전 | 적용 | 변경 내용 | 변경 이유 | 평가 결과 |
|---|---|---|---|---|
| `policy-rerank-v1` | #229 (현재 운영) | 최초 버전. 입력: 사용자 정보 5개(나이·소득 구간·지역·주택·취업 상태, 식별 정보 제외)와 후보 한 줄 요약(후보 번호, 정책명, 유형, benefitKind, 나이·자격 80자, 추출 금액·지원 내용 90자, 지역·시·군·구 한정, 신청 가능 여부, 특정 대상 집단). 출력: `{"selected":[{"policyId":번호,"reason":"40자 이내 한 문장"}]}` 후보가 N건 이상이면 반드시 N건(기준에 덜 맞는 정책은 뒤에 두어 채움, 특정 대상 전용·취업 상태 불일치는 채울 때도 제외). 기준: 받을 가능성(특정 대상 전용 제외, 마감 정책은 모자랄 때만) → 취업 상태 일치(학생·구직자에게 재직자 전용, 직장인에게 대학생·구직자 전용, 비자영업자에게 사업자 전용 제외) → 알 수 없는 개인 사정(학자금 대출 등) 필요 정책은 뒤로 → 금액이 크거나 지속적인 지원 우선 → 혜택 종류 섞기 → 원래 순서 | 규칙만으로는 직업 유형 불일치("직장인 든든한 한끼"를 구직자에게), 개인 사정 필요 정책("학자금 대출자 상환부담 완화"), 혜택 크기(천원의 아침밥 = 월세 지원)를 구분하지 못함 | 로컬 사용자 7명(`gpt-6.1-sol`, 2026-11-24): 7명 모두 10건 선택, 버린 ID 0건. 구직자(U3)·소득 미입력 직장인(U5)에서 "직장인 든든한 한끼"·"학자금 대출자 상환부담 완화" 제외, 직장인(U1·U5·U6)에서 대학생 천원의 아침밥 제외. 같은 사용자 2회 호출 겹침 9~10/10. 호출당 7.6~13.5초, 입력 약 6,000~9,200토큰, 출력 약 410~560토큰. 초안("최대 N건")은 3~9건만 골라 규칙으로 채우면서 제외한 정책이 다시 들어와 N건 필수로 바꿈. 남은 한계: 유주택·고소득 직장인(U6)·자영업자(U4)는 맞는 정책이 적어 학자금·심리상담 바우처가 중간에 들어감 |
